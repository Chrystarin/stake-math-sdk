# Colour Dice — Math SDK

Stake Engine math model for **Colour Dice**, a single-player port of the Filipino
*Perya* "Colour Game": three six-sided dice, each face showing one of six colours
(`yellow`, `blue`, `white`, `green`, `pink`, `red`). This package generates the
books, lookup table and config files the RGS needs to serve the game.

The matching web client lives in the separate `stake-web-sdk` repo at
`apps/colour-dice/` (see its README for the front-end and the math → web pipeline).

---

## How the game works

The player backs **one colour** per round. Three dice are rolled and the payout scales
with how many dice show the backed colour:

| Dice matching backed colour | Payout (gross return multiplier) |
| --------------------------- | -------------------------------- |
| 0 (miss)                    | 0× (loss)                        |
| 1 (single)                  | 2×                               |
| 2 (double)                  | 3×                               |
| 3 (triple)                  | **Lucky Wheel** award: 4× … 200× |

A triple spins a bonus wheel whose award (`4, 10, 20, 50, 100, 200`) is drawn by weight;
the top value `200×` is the win cap.

### Relative-outcome encoding

Every colour is statistically identical, so a round is stored **relative to the backed
colour** rather than as absolute colours:

- `MATCH` — a die showing the backed colour
- `C1` … `C5` — the five *other* colours, in the canonical order
  `yellow, blue, white, green, pink, red` with the backed colour removed

The web client substitutes the player's chosen colour for `MATCH` and the remaining five
colours for `C1..C5`, so one book renders correctly no matter which colour was backed and
replays are deterministic.

### RTP (analytic)

Because books are served **uniformly** (every book equally likely), the served RTP equals
the analytic RTP:

```
P(1 match) = 75/216   P(2) = 15/216   P(3) = 1/216
base   = 75/216 · 2 + 15/216 · 3            = 0.902778
wheel  = Σ(value · weight) / Σ(weight)      = 14.538   (expected triple award)
RTP    = 0.902778 + (1/216) · 14.538        ≈ 0.9701
```

- **RTP:** ≈ 0.9701
- **Win cap:** 200×
- **Bet modes:** one — `base`, cost `1.0`

All of these are constants in [`game_config.py`](game_config.py) (`paytable_matches`,
`wheel`, `rtp`, `wincap`), so tuning the game means editing that file and re-running.

## Round events

Each simulated round emits these book events (consumed by the web client in order):

| Event         | Purpose                                                             |
| ------------- | ------------------------------------------------------------------- |
| `reveal`      | The three dice (`MATCH`/`C1..C5`) + `selectedCount` (matches)        |
| `wheelSpin`   | Emitted only on a triple; carries the wheel `multiplier`             |
| `setTotalWin` | The round's total win amount                                        |
| `finalWin`    | Final settled win (drives the web win overlay)                      |

## File structure

```
games/colour_dice/
├── run.py                 # Entry point: simulation params + create_books/generate_configs
├── game_config.py         # GameConfig: colours, paytable, wheel, RTP, wincap, bet modes
├── gamestate.py           # run_spin(): rolls the 3 dice, spins the wheel, emits events
├── game_override.py       # reset_book / win-criteria repeat hook
├── game_executables.py    # (thin) game-specific executables layer
├── game_calculations.py   # (thin) game-specific calculations layer
├── game_events.py         # re-exports the shared event helpers
└── library/               # GENERATED — do not hand-edit
    ├── books/                     # human-readable .jsonl (uncompressed runs)
    ├── lookup_tables/             # per-book id / probability / payout CSVs
    ├── configs/                   # math + front-end config JSON
    └── publish_files/             # the 3 files the RGS needs (see below)
```

Only the `*.py` source is committed; everything under `library/` is regenerated by `run.py`.

## Prerequisites

- **Python ≥ 3.12** with PIP (Rust/Cargo only needed if you enable the optimizer, which
  this game does not use).
- From the **repo root** (`stake-math-sdk/`), create the virtual environment once:

  ```sh
  make setup
  ```

  This creates a `env/` venv and installs dependencies (including `zstandard`, which the
  web client's book-import script also relies on).

---

## Running

From the repo root (`stake-math-sdk/`):

```sh
make run GAME=colour_dice
```

Or call the run-file directly with the venv's Python:

```sh
# Windows
env/Scripts/python.exe games/colour_dice/run.py

# macOS / Linux
env/bin/python games/colour_dice/run.py
```

Default parameters in [`run.py`](run.py): `100,000` base simulations, batch size `50,000`,
single thread, zstd compression **on**. Output lands in `library/`, and the three files
required for RGS publication are written to `library/publish_files/`:

| File                       | Contents                                              |
| -------------------------- | ----------------------------------------------------- |
| `books_base.jsonl.zst`     | zstd-compressed game logic (one round per line)       |
| `lookUpTable_base_0.csv`   | `id, probability, payoutMultiplier` per round         |
| `index.json`               | mode manifest (name, cost, events + weights filenames)|

### Inspecting output in human-readable form

To eyeball the JSON, run a small uncompressed batch by editing [`run.py`](run.py):

```python
compression = False
num_sim_args = {"base": 100}
```

then re-run. `library/books/books_base.jsonl` will contain 100 pretty-printed rounds, each
with an `id`, its `events`, and a `payoutMultiplier` (which matches the value in
`library/lookup_tables/lookUpTable_base.csv`).

## Publishing / using the results

- **RGS:** upload the contents of `library/publish_files/` (the `index.json`, `.jsonl.zst`
  and lookup CSV) via the Stake Engine dashboard.
- **Web client:** after a run, refresh the offline sample books used by the front end:

  ```sh
  # from stake-web-sdk/apps/colour-dice
  pnpm --filter colour-dice sync-math-books
  ```

  That script shells out to this repo's Python venv to decompress `books_base.jsonl.zst`
  and write a sampled TS module for offline dev/preview play.
